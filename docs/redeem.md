# 兑换码

`redeem` 是独立可选插件，要求核心 `0.4.0` 和访问账户插件 `access 1.4.0` 或更新版本。它不依赖商业模式；自用、公益和商业站点都可使用。停用插件后，兑换入口及接口一起关闭，兑换码、记录和已经发放的权益保留。

普通用户先注册或通过已配置的第三方服务登录，再在用户前台“兑换码”填写兑换码。账户注册由独立注册或 OAuth 插件负责，兑换不会另外创建账号。管理员在后台“兑换码”创建、停用和查看兑换码，在“兑换记录”查看处理结果。

## 兑换内容

| 内容 | 行为 |
| --- | --- |
| 访问权益 | 设置流量额度、节点分组和期限，并开始新的流量周期；已有有效期会继续延长 |
| 追加流量 | 增加当前账户额度，要求已有基础访问账户 |
| 延长期限 | 延长当前账户期限，保留额度与分组，要求已有基础访问账户 |
| 重置流量 | 开始新的流量周期，要求已有基础访问账户 |
| 余额 | 入账到商业钱包；只有安装并启用商业运营插件时可用 |

余额金额以整数分传递，界面以元显示。期限支持天、日历月和长期；日历月不会固定换算成三十天。总兑换次数与每账号兑换次数独立设置，`0` 表示不限。兑换码的到期时间限制发起新兑换，已经登记的处理中兑换继续完成。

兑换码创建后不变；需要不同的码时另建记录。已有兑换记录或历史用量的码不能删除，可以停用。这样已兑换、处理中和旧版本用量都能继续核对。

## 处理与重试

兑换先保存记录并预留次数，再调用访问账户或钱包发放权益。已预留的兑换会占用次数，其他用户不能重复领取同一名额。权益和余额采用稳定操作编号；网络失败、插件重启或再次提交不会重复发放。

结果为“处理中”时，用户可以稍后重试同一码；后台定时任务也会继续处理。发放成功但记录写回中断时，重试会确认同一发放结果。记录保存兑换当时的权益快照，之后修改兑换码不会改变已经登记的兑换内容。

## 接口

路径以 `/api/v1/extensions/redeem` 为前缀，成功响应为 `{"data":...}`。所有兑换需要有效用户会话。

| 方法与路径 | 用途 |
| --- | --- |
| `GET/POST /codes` | 管理员查看或创建兑换码 |
| `PATCH/DELETE /codes/{id}` | 管理员修改或删除未使用的码 |
| `POST /redeem` | 当前用户兑换，参数为 `code` 和 `requestId` |
| `GET /claims` | 普通用户读取自己的记录；管理员读取全部 |
| `GET /claims?mine=1` | 只读取当前用户的兑换记录，管理员也适用 |

客户端为一次提交生成稳定的 `requestId`，失败重试保留它，成功或更换兑换码后生成新值。每账号限兑一次的码可省略该字段；允许同账号多次兑换的码必须提供它。

```json
{"code":"运营方提供的兑换码","requestId":"当前提交的唯一编号"}
```

完成返回 `status=redeemed`。已经保存、暂未完成发放时返回 HTTP `202`、`status=pending`；这表示兑换已登记，不能当成未提交而更换操作编号重复申请。历史接口不向普通用户返回内部开通编号或其他用户数据。

## 从旧版本升级

旧 `sharing` 的码和记录、商业插件中的余额兑换卡，通过独立的一次性工具搬到本插件。它不提供旧接口兼容层，不重新发放已经完成的权益，也不删除旧数据库记录。完整操作见 [兑换码数据升级](redeem-migration.md)。

SSPanel、V2Board、Xboard 的原码规则存在差异，面板导入插件默认只归档这些原始表，不会让旧码自动生效。不能把模板级限用、随机奖励或套餐规则直接降成单码次数。需要激活时，先确认目标规则能完整表达并单独转换。
