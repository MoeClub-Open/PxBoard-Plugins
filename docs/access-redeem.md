# 访问账户与兑换码

`access` 保存用户的连接凭据、流量额度、到期时间、节点分组、限速和设备限制。普通用户先注册或登录，再通过独立的 `redeem` 插件兑换访问权益；商业购买则由 `commerce` 调用同一套开通接口。注册、兑换码和商业功能各自独立。

## 访问账户

每个用户对应一个访问账户。账户编号创建后保持不变，NodeRS 使用该编号关联流量统计。导入用户保留原编号、连接凭据、已用流量及现有权益。

账户只有在核心用户启用、访问状态正常、未到期且仍有可用流量时下发到节点。不限流量需要显式开启，额度为零不会自动成为无限流量。用户只能读取自己的账户，管理员可以管理全部账户。

流量报告根据节点、批次和用户去重；同一批次重投不会重复扣量。手动重置流量会开始新的用量周期，历史统计仍保留。周期重置支持固定天数与带时区的日历规则；到期前尚未触发的规则不会反复改写，实际重置使用核心事务批量保存。

开通权益以业务 `grantId` 去重，退款只允许撤销当前账户最新一笔尚未退回的权益。权益使用明确的先后序号区分，同一秒开通的多笔订单仍按实际开通顺序处理。流量包、重置包或单独延时包需要先有基础账户。

## 兑换码

管理员在独立兑换码插件中创建访问权益码，可设置流量、期限、节点分组、总次数和每账号次数。普通用户登录后，在用户前台“兑换码”输入码值；兑换不创建账号。注册是否开放由独立注册插件控制。

兑换先保存记录并预留次数，再通过稳定的 `grantId` 发放权益。网络中断、插件重启或同一提交重试不会重复开通。暂未完成的记录保留为“处理中”，用户可重试，后台也会继续处理。记录保存兑换时的权益，后续修改码规则不会改变已登记的兑换。

普通访问权益码不需要商业插件。余额兑换码只有在商业插件安装并启用时才能入账，账本与访问权益分别处理。码的管理、兑换接口和重试规则见[兑换码文档](redeem.md)。

## 内部接口

以下路径位于 `/api/v1/extensions/access` 下，由核心校验调用插件权限。普通用户不能直接调用。

| 方法与路径 | 允许调用方与用途 |
| --- | --- |
| `GET /internal/clients` | nodes、subscriptions 读取当前可用账户 |
| `GET /internal/clients?userId=...` | nodes、subscriptions 读取指定用户的当前可用账户，返回数组 |
| `GET /internal/accounts` | nodes 读取稳定编号与用户映射，不包含连接凭据或权益历史 |
| `GET /internal/accounts/{user}` | commerce 或管理员读取指定用户权益；不存在时返回 `null` |
| `POST /internal/grant` | commerce、redeem 按业务编号开通权益 |
| `POST /internal/revoke` | commerce 按业务编号撤销最新权益 |

旧 PxBoard 分享码、充值卡及其记录的搬入方式见[兑换码数据升级](redeem-migration.md)。Xboard / V2Board 的兑换码及使用记录可迁入独立兑换码模块；具体范围见[迁移文档](migration.md)。
