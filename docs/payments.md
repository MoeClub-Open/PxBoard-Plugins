# 支付网关

`payments` 1.4.0 提供 Stripe 与易支付收银台、回调验签和支付流水，依赖商业插件 `commerce`。需要核心 0.4.0 或更新版本。

## 支付渠道

管理员在“支付渠道”添加独立渠道。填写面板的 HTTPS 根地址，支付回调使用该地址下的 `/api/v1/extensions/payments/webhooks/{渠道ID}`。修改密钥时留空会保留原值。

Stripe 使用支付密钥及独立的回调签名密钥。收银台金额以分传给 Stripe，币种为 CNY。

易支付使用 HTTPS 网关地址、商户号、通信密钥与付款方式。网关地址保留服务商要求的路径，不要填写末尾的 `/submit.php`；插件会自行追加该路径。付款方式直接传入网关的 `type` 参数，默认 `alipay`，也可以填写 `wxpay`、`qqpay` 或网关要求的其他值。Linux DO Credit 的易支付接口使用 `epay`。

易支付请求包括 `pid/type/out_trade_no/notify_url/return_url/name/money`；金额从整数分转换成两位小数。请求签名按参数名排序、排除空值及 `sign/sign_type`，用 `key=value` 和 `&` 连接后追加通信密钥，再计算 MD5。回调还要求商户号一致、`trade_status=TRADE_SUCCESS`，并检查订单金额、币种与支付流水的唯一性。

## 从原面板手动搬迁渠道

支付配置属于站点管理配置，不随账户导入自动启用。先确认源渠道使用的协议和服务商参数，再手动填入新渠道；密钥不要放入迁移报告或仓库。

| 原易支付配置 | 新渠道字段 |
| --- | --- |
| `name` | `name` |
| `url` | `gatewayUrl` |
| `pid` | `merchantId` |
| `key` | `apiKey` |
| `type` | `paymentType`；未配置时使用 `alipay` |
| 源面板回调域名 | 使用新面板的 `publicUrl`，新渠道生成自己的回调路径 |

旧面板待支付订单、旧收银台会话和回调地址不能直接交给新渠道处理。最终冻结时需重新确认没有待支付或开通中订单；存在时应先在源面板结清或取消并退回已占用余额，再重新导出用户余额与权益。切换后关闭旧面板写入；需要核对的晚到付款单独对账，不能重复触发新套餐开通。

曾使用的渠道保留后续回调能力，不能直接删除；需要停止新收款时停用渠道。支付流水与订单不一致时进入人工核对，管理员登记处理结果不会自动改余额或开通套餐。
