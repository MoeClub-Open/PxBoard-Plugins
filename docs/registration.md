# 账户注册

`registration` 是独立可选插件，版本 `1.0.0` 要求 PxBoard 核心 `0.4.0` 或更新版本。它创建普通用户、管理全局注册开关并保存推广来源，不依赖商业、支付、推广、兑换码或访问权益插件。

分享和商业模式的默认组合安装此插件，自用模式默认不装。模式只决定默认安装组合：主动安装并启用本插件后，是否开放注册仅由“账户注册 → 开放注册”决定，不会随模式切换暗中关闭。

## 使用

启用插件后，访客可在 `/register` 填写邮箱、至少 10 位密码及可选姓名。创建的用户使用普通成员身份。注册不会自动赠送流量、套餐或余额；站点可以另装兑换码插件发放权益，或安装商业插件提供购买。

后台“账户注册”只有一个全局“开放注册”开关，默认开启。关闭后，注册表单不再公开，直接请求注册接口也会被拒绝。停用或卸载插件同样关闭普通注册，已有账号、密码和业务数据保留。

## 第三方登录

OAuth `1.1.0` 通过本插件只读的注册政策决定能否创建新账号。允许新第三方账号注册，需要同时满足：

- `registration` 已安装并启用，且开放注册。
- OAuth 对应登录服务启用“允许新账号注册”。

未安装本插件、注册关闭或政策读取失败时，OAuth 不创建新账号。已有第三方绑定仍可登录，已登录用户仍可绑定自己的第三方账号。两插件之间没有强制安装依赖，因此只需要既有账号第三方登录的站点可以不安装普通注册。

## 推广来源

`/register?ref=<推广来源>` 中的 `ref` 通过隐藏字段保存，用户表单不增加“邀请人”输入项。OAuth 发起登录授权时也会保留同一查询参数。

用户与首条注册记录在一个事务内创建。注册记录保存稳定的 `userId`、可选 `referral` 和 `registeredAt`；后续发布 `account.registered` 事件，是否安装推广插件都不影响新用户登录。

事件写入队列失败时，原记录保持 `registrationPending=true`，通过后续 `system.tick` 重试。事件已入队但状态保存失败时可能再次发送，因此接收插件必须按 `userId` 去重，不能按每次变化的事件 ID 重复建立关系或奖励。推广来源本身不代表已授权的奖励，由可选推广插件核对来源和规则后处理。

注册记录持续保留。后安装的推广插件可读取只读注册来源接口核对历史归因；注册插件不会直接写入推广数据，也不会因推广处理失败撤回已创建的账号。

## 接口

以下路径以 `/api/v1/extensions/registration` 为前缀，成功返回 `{"data":...}`。

| 方法与路径 | 权限与用途 |
| --- | --- |
| `POST /register` | 公开；参数 `email/password/name?/referral?`，返回 `{id,message}` |
| `GET /settings` | 管理员；返回包含唯一配置的数组 |
| `PATCH /settings` | 管理员；参数 `{enabled:boolean}` |
| `GET /internal/policy` | OAuth、核心或管理员；返回 `{enabled:boolean}` |
| `GET /internal/registrations` | 推广插件或管理员；返回 `[{userId,referral?,registeredAt}]` |
| `GET /_capabilities` | 仅内部核心调用；返回 `{"auth.registration":boolean}` |

注册表单通过标准插件 `auth` 声明提供，继续使用核心通用注册页面。配置资源使用单记录接口，不需要拼接记录 ID 的重复路径。

`account.registered` 数据示例：

```json
{
  "userId": "目标用户ID",
  "referral": "可选推广来源",
  "registeredAt": "2026-10-27T00:00:00Z"
}
```

事件来源为 `registration`；OAuth 新账号的同名事件来源为 `oauth`。接收方应同时检查事件来源和用户标识。密码只提交给核心创建用户，不保存到插件注册记录或事件中。
